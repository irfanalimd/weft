# Security review W4: accounts, sessions, notes

An independent pass over `crates/weft-server/src/{auth,api,db,lib,store}.rs` (2026-10-26), against `docs/WALL.md`.
Fixes were verified against a release server on 127.0.0.1:7993 (temp data dir, 40-char bootstrap token) with curl and a
Node WebSocket client. `cargo fmt`, `clippy -D warnings` and `cargo test --workspace` pass.

## Findings

| # | Sev | Location | Issue and exploit | Status |
|---|---|---|---|---|
| 1 | **High** | `auth.rs` `verify_password`/`hash_password`; `api.rs` `login` | **Argon2 memory/CPU exhaustion, and the throttle could be raced.** `check` ran before verification and `fail` after it, so N concurrent bad logins from one IP all passed the check. Each spawned a 19 MiB Argon2 run on the blocking pool (up to 512 threads, so about 10 GB), which is enough for one unauthenticated client to OOM the VPS. It also allowed unlimited password guesses per burst. | **Fixed.** A global semaphore caps concurrent Argon2 runs at `min(cores, 4)` (503 after a 10 s wait). The new `Throttle::attempt` checks and records the attempt atomically, and `forgive` takes it back on success (login, change password). Verified: 30 concurrent bad logins now give 5×401 and 25×429 (before the fix all 30 were hashed). |
| 2 | Medium | `auth.rs` `api_middleware` | **A missing `Origin` was accepted on cookie-authenticated state-changing requests.** `origin_allowed` returns true without `Origin`, which exists for native WebSocket clients. Browsers always send `Origin` on POST/PATCH/DELETE, so only a non-page context sends a cookie without one. The JSON Content-Type plus SameSite=Lax mitigated this, but defense in depth was missing, and logout (which has no JSON requirement) relied on it alone. | **Fixed.** Non-safe methods that carry a `weft_session` cookie but no `Origin` get 403. Cookieless clients (e.g. curl login) are unaffected. Verified 403/201/403 for no-Origin/same/evil Origin, and 403 for a no-Origin logout. |
| 3 | Medium | `lib.rs` `ws_note_route` → `connection` | **WebSocket auth TOCTOU.** Ownership and the session were checked before the upgrade, but the socket was registered for revocation only after the handshake. A logout, disable, password change, note delete or user delete in that window missed the socket, which stayed open and kept syncing the note indefinitely. | **Fixed.** After registering, `connection` re-checks `session_user` and `note_owner`, and closes with 4001 if either check fails. |
| 4 | Medium | `lib.rs` `join_inner`, `admit` | **Anonymous docs could starve private notes.** Rooms (`WEFT_LIMIT_ROOMS`) and connections (`WEFT_LIMIT_CONNS`) were one shared pool. Anyone holding 64 sockets on each of about 32 IPs or /64s could fill all rooms with anonymous docs, so every owner got "server has too many documents open" on their notes. | **Fixed.** Anonymous docs and anonymous sockets may use only ¾ of each cap (`anon_share`). The last quarter is reserved for authenticated note sockets. Verified with `WEFT_LIMIT_ROOMS=4`: the 4th anonymous doc is refused and the note still opens. |
| 5 | Low | `auth.rs` `Throttle` | Throttle maps were bounded only by the hourly sweep. | **Fixed.** `record` sweeps inline when the maps exceed 100k keys. Growth is also rate-bounded now by #1. |
| 6 | Low | `api.rs` `login` | Targeted lockout: 10 bad logins per 15 min with someone's username lock that account (from any IP). | Accepted. This is the specified design, and it is the trade-off for spray resistance. |
| 7 | Low | `lib.rs` `ws_note_route` | It returns 403 for someone else's note but 404 for a missing one (REST returns 404 for both), which leaks whether an id exists. | Accepted. The ids are 16-char base58 (about 94 bits), and WALL.md specifies 403. |
| 8 | Low | `api.rs` `admin_patch`/`admin_delete` | Last-admin check is check-then-act; two admins demoting each other concurrently can leave zero admins. | Accepted. This needs two cooperating admins, and recovery is via the DB. |
| 9 | Low | `api.rs` `list_notes` | `GET /api/notes` (no `q`) is unpaginated, and the note count per user is unlimited. | Accepted. The users are created by the admin and only see their own notes. The JSON body is capped at 2 MB by axum (and 1 MB by Caddy). |
| 10 | Low | `lib.rs` `/ws/n` sockets | An open note socket outlives its session's expiry (it is revalidated only on revocation events). | Accepted. Expiry is sliding and 30 days, and every revocation path closes the socket. |
| 11 | Info | `lib.rs` `/api/stats` | The open-room count includes note rooms. | Accepted (it's only a count). |

## Verified OK (no change)

- **Argon2id** is used with m=19 MiB, t=2, p=1. The dummy hash for unknown or invalid usernames and over-long passwords uses the same params and is warmed at start. Login input is capped at 1024 chars.
- **Bootstrap:** the token is ≥32 chars and trimmed. `ct_eq` compares SHA-256 digests in constant time. Setup is refused once users exist, and `create_first_admin` counts and inserts under the connection mutex. Verified: 3 concurrent setups give 1×200 and 2×403.
- **Sessions:** the token is 256-bit (`rand` CSPRNG) and only its SHA-256 is stored. The cookie is `HttpOnly; Secure; SameSite=Lax; Path=/`. The token format is checked (64 hex). Sliding extension happens daily. Logout deletes the session and closes its sockets. A password change or admin reset revokes the other sessions and closes their sockets. Disable and delete revoke everything and close sockets (verified: the socket got 4001 on disable).
- **Roles:** the role and disabled flag are re-read from the DB on every request (`session_user` joins `users`), so a demotion takes effect immediately (verified: 200 becomes 403).
- **IDOR:** every note route goes through `get_note(id, owner)` or `WHERE owner_id`. Bob got 404 on PATCH, DELETE and export for the admin's note, empty search results, 403 on `/ws/n`, and 409 when reusing the id.
- **Namespaces:** `RoomKey::{Doc,Note}` are separate registry keys over separate `docs/` and `notes/` stores. `/ws/:id` and `/api/docs/:id/export.md` never see notes (verified 404). `from_doc` reads `RoomKey::Doc` only.
- **Injection:** every SQL value is a bound parameter; the only `format!` interpolations are constant column lists and filters. The FTS sanitizer strips `"`, quotes each term as a prefix phrase and caps it at 16 terms. Note and doc ids are strictly validated before any path join, so path traversal is impossible.
- **Client IP:** `X-Forwarded-For` is trusted only from a loopback peer. Caddy 2.6 without `trusted_proxies` replaces it with the real client IP. IPv6 is grouped per /64. Username throttling is case-insensitive (verified: 10 case variants from 10 IPs, then 429).
- **Logs:** no passwords, tokens or cookies are logged (grep of the run log came back clean). Logged usernames are pre-validated, and the Origin is Debug-escaped.
- **CSWSH:** `/ws/n` applies the Origin check before the upgrade (verified: an evil Origin gets 403).
